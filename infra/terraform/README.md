# Regis infrastructure — ap-south-1

> **Status: written, never applied.** No AWS account has run this. Treat it as a
> reviewed starting point, not a description of a running system. Until someone
> applies it and records the result here, **do not repeat the India
> data-residency claim to a customer** — the region pinning below is intent, not
> yet evidence.

## What this covers

The stateful pieces the application cannot recreate for itself:

| Resource | Notes |
|---|---|
| RDS Postgres 16 | Storage encrypted with the project KMS key. Master password generated by RDS into Secrets Manager, so no credential literal enters Terraform state. Multi-AZ and deletion protection only in `prod`. |
| ElastiCache Redis 7 | Arq queue plus the login rate-limit counters. Encrypted at rest and in transit — connect with `rediss://`. |
| S3 evidence bucket | KMS SSE, versioning on, public access blocked, and a bucket policy denying non-TLS requests. |
| KMS key | One key for all three, rotation enabled. |

`var.region` has a validation rule rejecting anything outside `ap-south-*`. That
is deliberate: data residency is a contractual claim to an RBI-regulated buyer,
so moving the region should require editing the validation and noticing why.

## What this does NOT cover

- **Compute.** No ECS/App Runner service yet. Run the images from
  `docker-compose.yml` against these endpoints first and see what the app
  actually needs before committing to an orchestrator.
- **Networking.** Expects an existing VPC, two private subnets, and the
  application security group. Pass them in.
- **State backend.** Add an S3 backend with DynamoDB locking before more than
  one person applies this.
- **DNS, certificates, WAF.** The rate limiter assumes a proxy that sets a
  trustworthy `X-Forwarded-For`; whatever terminates TLS must do that.

## Applying

```bash
cd infra/terraform
terraform init
terraform plan  -var env=staging -var vpc_id=… -var 'private_subnet_ids=["subnet-a","subnet-b"]' -var app_security_group_id=…
terraform apply -var env=staging …
```

Then wire the app from the outputs — read the DB password from the Secrets
Manager ARN at boot rather than baking it into an image:

```
REGIS_ENV=staging
REGIS_DATABASE_URL=postgresql+psycopg://regis:<from-secret>@<database_endpoint>/regis
REGIS_REDIS_URL=rediss://<redis_endpoint>:6379/0
REGIS_S3_BUCKET=<evidence_bucket>
REGIS_AWS_REGION=ap-south-1
```

## The one thing that will silently break tenant isolation

Migration `0002` sets `FORCE ROW LEVEL SECURITY` on every tenant table.
**Superusers bypass RLS.** The application must connect as a non-superuser role,
or every tenant boundary in the product is inert while every test still passes.
Create the app role explicitly after the first `terraform apply`, and never point
the app at the RDS master user.
